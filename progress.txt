## Podcast 同期の「無料・完全自動」化（2026-07-05 実装完了）

### 調査で判明した実態
- 配線自体は正常: リンク Notion ページ = `NOTION_PODCAST_DB_ID`（1db26482…80b9…6ec）、唯一の data source（…8160-ad77…）= generate スクリプトのハードコード ID と一致。
- **週次自動更新は約3ヶ月死んでいた**: `gh run list` で 5月以降の scheduled 実行が**毎回失敗**（今朝 07-05 も）。原因は 4月の pnpm 移行で `package-lock.json` が消えたのにワークフローが `npm ci` のままだったこと（`npm error … can only install with an existing package-lock.json`）。bot 最終成功コミットは 2026-03-29。
- ライブ API は毎回 `categoryBasedPositioning`＋`hasEmbeddings:false` で、静的 JSON の埋め込みを無視する設計だった。
- OpenAI はワークフローに繋がっておらず、埋め込みは元々一度も生成されていなかった（ヒーロー文言「AI embeddings」は当初から不正確）。

### 実装した修正（すべて無料・APIキー不要）

## Home の Figma Plugins カードがモバイルでタップ不発（2026-07-28）
ユーザー報告「Figma Plugins & Widgets をtapしても詳細に行かない」。
- **真因**: Home の Figma カードは `<Link>` で包まれているが、サムネイルの `PluginCardDeckThumb`（3枚のプラグインカードを扇状に重ねた装飾）が hover で `setActive`→カードを 1.08倍に scale する。**タッチ環境では最初のタップで `onMouseEnter` が発火→transition 中にカードが指の下で動く→ブラウザが後続の click を抑制**し、親 `<Link>` へ届かない（＝1タップ目は拡大だけで遷移しない）。デスクトップ（マウス）では発生しない。
- **修正**（`PluginCardDeckThumb.tsx`）: hover 可能デバイス（`(hover: hover) and (pointer: fine)`）でのみ hover-scale を有効化。タッチ環境（`canHover=false`）では装飾デッキを `pointer-events:none` にし、タップが素通りで `<Link>` に届くように。デスクトップの hover アニメは不変。
- **検証**: 本番でデッキに `pointer-events:none` を適用するとサムネイル上の最前面要素が `<Link>` 配下に変わり（passthrough）、タップで `/work/figma-plugins` へ遷移することを確認。デスクトップ経路（デッキ最前面＋clickバブリング）も遷移維持。
- 教訓: タッチ端末では「hover で要素が動く」装飾はタップを殺す。装飾は `(hover: hover)` 限定にし、タッチでは `pointer-events:none` でリンクを優先する。

## 応募提出用 PDF ポートフォリオ — 方針決定（2026-07-29）

- **調査結果: PDF 基盤は完全にゼロ**。`playwright`/`puppeteer`/`@react-pdf/renderer` いずれも未インストール、print CSS（`@media print`/`@page`/`print:`）の使用例がリポジトリ全体で0件、`/print` ルートも無し。
- **生成方法は「コード生成」に決定**（専用 print ルート + Playwright `page.pdf()`）。Figma 手組みは `cvData.ts` との二重管理になり CV 更新のたびに手作業が発生するため不採用。`pnpm generate:pdf` で EN/JP 2版を何度でも再生成できる状態を目指す。
- **掲載対象は「仕事のみ、personal は入れない」**（ユーザー判断）→ Ukiyoe / Gym Dashboard / Google UX は除外。**クライアント名はサイトと同じく全て匿名**（PDF は転送・保存されやすく統制が効かないため）。
- **v1 のスコープ = 表紙 + レジュメ2ページ + Airline Design System 3ページ**。画像0枚の案件は後回し（下記TODO）。
- **判明した技術的な壁3つ**:
  1. **Collapsible 問題** — `WorkProjectCard` の `CollapsibleContent` は閉じている間 DOM からアンマウントされる。素朴に `page.pdf()` すると今回追加した detail が全部消える。→ `forceOpen` でも複製でもなく、**乖離してはいけないロジックだけ `src/cv/{format,selectors,fontClasses}.ts` に抽出**して print 側と共有する方針。
  2. **A4 は 793.7 CSS px で `md:` ブレークポイント（768px）を超える** → 印刷時もデスクトップのトークン（`--text-size-4xl: 56px`）が生きてしまう。→ `:root` や `globals.css` を触らず **`.pdf-doc` ラッパーに `--text-size-*` を置いて継承で勝たせる**（ライブサイトへの影響が構造的にゼロ、かつ画面プレビュー可能）。
  3. **フォントが3系統に分裂** — `globals.css:17` のリモート Google Fonts `@import` が実際の Space Grotesk / Noto Sans JP の供給元で `next/font` 変数は上書きされ死んでいる。EN 本文はシステムの Helvetica Neue で埋め込まれない。→ print ツリー限定で **EN本文を自前ホストの Switzer に、Space Grotesk / Noto を `var(--font-*)`（next/font のビルド時セルフホスト）に**差し替え、オフラインでも同一 PDF になるようにする。
- **画像の穴（最大の課題）**: personal を除外した結果、画像を持つ work 案件がほぼ無い。Airline は7枚あるがヒーローが **784×716 しかなく全資産中で最弱かつ最重要**。ゆめみ5案件と大学校友アプリは **0枚**（Notion エクスポートで画像が全滅）。

## PDF の図版は根本的に作り直し — TODO 化（2026-07-31）

### 具体的に何がダメか
1. **`token-architecture.webp` がキャプションと別物**。「2層トークンアーキテクチャ — Primitive を Semantic にマッピング」というキャプションに対し、図の中身は「旧チケット17件 → 新チケット17市」「1 solution検討」「7 Native Flutter比較」「4 Figma制約条件」「2 全体スケジュール」、矢印は「統合」「移行」＝**チケット移行フロー図**。トークンの本文の横にこれが置かれている。`app/[locale]/work/airline-design-system/page.tsx` の `captionToken` も同じ組み合わせなので**サイト側から要修正**。
2. **JP 版の方が問題が目立つ**。キャプションも図も日本語なので、日本語話者の採用担当には不一致がはっきり見えてしまう。逆に EN 版には日本語の図版が入っているという別の問題がある。
3. **`system-structure.webp` が 784×716 しかない**（6ページ目のヒーロー）。2倍ルールで104mmまでしか置けず、生成のたびに解像度警告。全資産中で最弱なのに最重要の位置。
4. **画像0枚の案件が大半**。personal を除外した結果、ゆめみ5案件＋大学校友アプリは図版ゼロのまま文字だけのページになっている。

## アートディレクション刷新の検討 — /preview に2案プロトタイプ（2026-07-31）

### seremoni.com の実測値（app.CleFsfex.css から抽出）— 推測でなく一次情報
- 色は**5色だけ**: salt `#ebe8de`（地）/ black `#2b2b2b`（純黒ではない）/ pink `#ea677e` / stone-blue `#85a9c0` / white。罫線 `#c9c9c9`。

- 素材: `autoplay muted loop` の動画1本（poster付き）+ 静止画36枚。角丸 21–25px、ドーム/円マスク。
